- Why Cloud Run: needs full Node (Prisma, next-auth, Stripe, request-time `fs` for the blog posts in `src/app/posts`). Rule: `~/dev/work/lumio-studio/CLAUDE.md` "WEB HOSTING RULE"; edge worker: `web-apps/lumio-edge/CLAUDE.md`.
- Runtime: Cloud Run service `ensi-home`, project `lumio-web-hosting` (account contact@lumiostudio.co), europe-west1, https://ensi-home-310163861885.europe-west1.run.app. Settings: min-instances 0, max-instances 1, 1 GiB, `--cpu-boost`, `--no-invoker-iam-check` (org policy forbids `allUsers`), runtime SA `ensi-home-run@lumio-web-hosting.iam.gserviceaccount.com`.
- Request path (after cutover): `ensihome.solace.com.tr` -> Worker `lumio-edge` (host already in its `ORIGINS`, deployed) -> Cloud Run. Verified 2026-10-26 on the run.app URL against production: /, /en, /blog, /ensi-home, /knowledge-base, /legal, /api/posts, /robots.txt, /sitemap.xml, 404 all match status and size (/tr is a 307 on both); title "Ensi Home".
- Status: zone `solace.com.tr` is PENDING in our Cloudflare, so DNS is NOT cut over; production still resolves through Vercel DNS until the owner switches the nameservers.
- CUTOVER (once the zone is ACTIVE; the script skips hosts on non-active zones):
  `python3 -I ~/dev/work/lumio-studio/scripts/cf-migrate/cutover.py lumio-edge ensihome.solace.com.tr`
  Verify: `curl --resolve ensihome.solace.com.tr:443:104.16.0.1 https://ensihome.solace.com.tr/` returns 200 with `<title>Ensi Home` (allow ~1 min, 421/522 meanwhile). Rollback: detach the custom domain and re-add CNAME `cname.vercel-dns.com` (DNS-only).
- Env: plain (Cloud Run env): APP_URL, GITHUB_ID, GOOGLE_SITE_VERIFICATION_ID, NEXTAUTH_URL (set to https://ensihome.solace.com.tr; Vercel had http://localhost:3000), NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY, STRIPE_SUBSCRIPTION_PRICE_ID. Secrets (Secret Manager `lumio-web-hosting`, prefix `ensi-home-`): DATABASE_URL, GITHUB_SECRET, NEXTAUTH_SECRET, SENDGRID_API_KEY, STRIPE_SECRET_KEY, STRIPE_WEBHOOK_SECRET_KEY. Values copied from the Vercel project; originals stay there until the project is deleted (copy them to lumio-secrets-holder before that). Build-time placeholders for `src/env.mjs` live only in the Dockerfile build stage.
- Not verified: Prisma/DB-backed routes (auth, Stripe webhook, forms) were not exercised (no real DB call made); the Stripe webhook endpoint URL registered at Stripe points at the old host and moves with the domain at cutover.
- Deploy (remote Cloud Build, no local Docker): regenerate the config files if needed with `bash ~/dev/work/lumio-studio/scripts/cf-migrate/vercel-to-cloudrun.sh . ensi-home ensi-home ensi-home-run SENDGRID_API_KEY STRIPE_SECRET_KEY STRIPE_WEBHOOK_SECRET_KEY NEXTAUTH_SECRET GITHUB_SECRET DATABASE_URL` (gitignored `.env.production`, `cloudrun-env.yaml`, `cloudrun-secrets.txt`; then set NEXTAUTH_URL in the yaml to the production URL), then `gcloud run deploy ensi-home --source . --region=europe-west1 --project=lumio-web-hosting --account=contact@lumiostudio.co --quiet` (existing env, secrets and settings are kept on later deploys). `.gcloudignore` mirrors `.dockerignore`.
- Rollback: `gcloud run services update-traffic ensi-home --to-revisions=<previous>=100 …`, or re-point DNS to Vercel while the project still exists.
